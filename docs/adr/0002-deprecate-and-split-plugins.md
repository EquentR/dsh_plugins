# ADR-0002: 弃用 model-capabilities，并改为独立可选的插件包

- 状态：已接受
- 日期：2026-10-18
- 取代：无（ADR-0001 仍然有效）

## 背景

`model-capabilities` 当初存在的理由是一个具体的上游缺口：`llm-pi-ai` 的配置 schema 已经支持每模型的
`reasoningEfforts` 与 `input`，但自带的模型设置页没有编辑控件，用户只能手写 `settings.yaml`。

新版本 DSH 已经在产品内内置了模型能力设置，包括思考等级与多模态（图片输入）。这个缺口不再存在，
继续维护一个与内置设置界面重叠的第三方页面，只会带来两套写入路径和相互冲突的风险。

同时，仓库引入的三个新能力（Git 图谱、真会话删除、纯对话导师模式）来自一个统一的第三方仓库
（[yiiilin/dsh-plugins](https://github.com/yiiilin/dsh-plugins)，MIT）。该仓库把八个模块打进**一个**
bundle，安装即全装，只能靠开关逐个控制。实践中一次安装曾导致 DSH 崩溃，说明"一次装全套"的失败面太大：
任何一个模块的 Host 半出错，都可能影响整个 profile 的启动。

## 决策

1. **弃用 `model-capabilities`**：标记为 deprecated，保留源码与文档作为历史实现和迁移参考，不再
   适配新版本，不再建议安装。内置设置成为唯一受支持的路径。
2. **新能力一律按"一个插件 = 一个独立包"交付**：`git-graph`、`delete-session`、`mentor` 各自
   拥有独立的 `package.json`、`cordis.patch.yml`、Locale 资源和 README，互不依赖。
3. **每个包只插入一行 Loader 配置**，装一个就是装一个；不提供"整套安装"的聚合包，也不做
   安装后靠开关关闭未使用模块的设计。
4. **默认关闭能力型插件**：`mentor` 会创建子 Agent 并消耗模型额度，因此 `enabled: false`，
   显式启用后才工作；`git-graph` 与 `delete-session` 只在用户主动操作时产生副作用。
5. **不直接复用参考仓库的补丁结构**：包名、Client 模块 id、页签标识与样式归属统一改到本仓库的
   `@dsh-plugins/` 命名空间下，避免与该仓库同时安装时发生 id 冲突。

## 影响

- 用户可以按需安装单个插件，某个插件出问题时可单独移除，不必卸载整套。
- 代价是没有"一键全装"体验，且三个包的依赖与版本窗口需要在各自 README 中分别声明。
- 三个新插件都是**持久包**（顶层 `import`），不能用 `cordis_define` 动态加载；这与
  `model-capabilities` 的函数体形态不同，属于两类不同交付物，仓库文档需要分别说明。
- 兼容性窗口按 DSH `0.2.1-rc.2` 声明（`>=0.2.1-rc.2 <0.2.2`）。上游小版本变动时，需要重新核对
  各包 README 中列出的 Host 服务与 Client 槽位，而不是假定继续可用。
- 参考实现的验证基线（DSH `0.2.0-rc.2` / `0.2.1-alpha.2`）与本仓库声明的版本窗口不同，移植时的
  改动只涉及命名与打包边界，业务逻辑未改写；每个包的验证状态以其 README 的"验证"一节为准。
